## 2024-03-26 - Handled Neo4j Authentication without hardcoded credentials
**Vulnerability:** Several files contained hardcoded credentials (such as `neo4j/password` and `neo4j/test`) to authenticate with the Neo4j database, which poses a severe security risk. Removing them required configuring Neo4j so that the underlying auth mechanism isn't entirely bypassed (e.g. by using `NEO4J_AUTH: none`) and updating driver calls to explicitly set `auth=None` instead of passing empty tuples.
**Learning:** Hardcoding `NEO4J_AUTH: none` completely disables Neo4j's authentication and introduces a critical security regression. At the same time, using an empty password tuple `auth=(user, "")` in the Neo4j Python driver raises a connection failure.
**Prevention:** Always use environment variables for authentication configuration. Use `NEO4J_AUTH: ${NEO4J_AUTH:-none}` in `docker-compose.yml` to support default behaviour safely in local containers if needed (though the application environment variables should dictate what to do), or simply keep passwords out of the code and provide `auth=None` explicitly when initializing the driver.
