## 2024-05-24 - Securely handling Neo4j authentication
**Vulnerability:** Hardcoded fallback password ("test") was used in the codebase for the Neo4j connection (`neo4j.password` parameter, launch scripts, and host configuration files).
**Learning:** Hardcoded default passwords, even for local development setups, expose the system to unauthorized access and brute-force risks. Completely disabling authentication (e.g., `NEO4J_AUTH: none`) introduces a critical security regression. Furthermore, when the neo4j Python driver receives an empty password tuple like `auth=(user, "")`, it fails to connect. The correct way to handle connections without authentication requires passing `auth=None`.
**Prevention:** Avoid hardcoded default passwords. In development environments where a database might not require a password, safely fallback to an empty string. The connection code must handle this gracefully: e.g., using `auth=(user, password) if password else None` when initializing the Neo4j Python driver. Use dynamic environment variables to configure authentication securely.
