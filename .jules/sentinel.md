## 2025-02-24 - Hardcoded Database Credentials & Insecure Default Passwords
**Vulnerability:** Found hardcoded `NEO4J_AUTH: neo4j/password` in `services/graphs/docker-compose.yml`, an insecure default `NEO4J_PASSWORD=${NEO4J_PASSWORD:-test}` in `modules/memory/launch_unit.sh`, and a default parameter `"test"` for `neo4j.password` in the `modules/memory/packages/memory/memory/node.py` ROS 2 node.
**Learning:** Hardcoded credentials and insecure fallbacks in configuration files or launch scripts bypass access controls and can easily lead to unauthorized database access if these configurations are used in any non-local environments. They fail open by defaulting to weak credentials instead of failing securely when required secrets are missing.
**Prevention:** Never hardcode credentials in docker-compose files. Enforce the presence of sensitive environment variables using bash syntax like `${VAR?error message}` or in docker-compose like `${VAR?must be set}` so the application fails to start if secrets are not explicitly provided. Remove default credential parameters in application code.
