## 2024-05-18 - [Hardcoded Database Passwords in Launch and Config Files]
**Vulnerability:** Default database passwords (like `test` for Neo4j) were hardcoded in ROS 2 node parameters, launch scripts (`launch_unit.sh`), and host manifests (`hosts/motherbrain.toml`).
**Learning:** Hardcoding credentials in version control presents a significant security risk, even for default or local environments, as these credentials might inadvertently be used in production environments. We must rely on environment variables for sensitive data rather than code-defined defaults. Additionally, when removing password requirements in development (e.g. setting `NEO4J_AUTH: none`), the Python `neo4j` driver expects the `auth` parameter to be `None` rather than `(user, "")` which will fail to connect.
**Prevention:** Always use empty strings `""` for missing credentials in defaults and parameter definitions. Ensure development compose files use `NEO4J_AUTH: none` to disable auth completely, and explicitly pass `auth=None` to the driver when no password is provided.
