## 2024-03-22 - Hardcoded Neo4j Passwords Removed
**Vulnerability:** Default/hardcoded passwords ("test", "password") were being used for Neo4j database configuration in ROS parameter declarations, launch scripts, host configuration files, and docker-compose files.
**Learning:** Hardcoded default passwords create an immediate security risk, as databases can be accessed by unauthorized individuals if exposed. Even in local setups, fallback passwords shouldn't be valid default strings. Empty strings should be used instead for fallback passwords or database auth should be disabled explicitly for local development. Furthermore, when the password is empty, the python neo4j driver requires `auth=None` instead of `auth=(user, "")` or it will fail to connect.
**Prevention:** Use environment variables for sensitive configuration and use empty strings for defaults instead of 'test' or 'password'. In docker-compose, set `NEO4J_AUTH: none` to disable authentication entirely for local environments instead of using default credentials.
