## 2024-05-20 - Hardcoded Database Passwords
**Vulnerability:** The Neo4j graph database had a hardcoded default password ("test") in multiple places (`modules/memory/packages/memory/memory/node.py`, `modules/memory/launch_unit.sh`, `hosts/motherbrain.toml`) and the docker-compose file (`services/graphs/docker-compose.yml`) used `NEO4J_AUTH: neo4j/password`. This could allow unauthorized access to the database.
**Learning:** Default fallback configurations in launch scripts, host configs, and parameter declarations often inadvertently create hardcoded credentials that get propagated to production environments.
**Prevention:** Avoid default passwords for databases entirely. Use empty strings for passwords in ROS parameter declarations, launch scripts, and host configurations. In `docker-compose.yml` for local dev, explicitly disable authentication (e.g., `NEO4J_AUTH: none`) if appropriate, or mandate external secret provisioning. Note: When configuring the Neo4j Python driver without authentication due to an empty password, the `auth` parameter must be explicitly set to `None` rather than a tuple with an empty string `(user, "")` to prevent connection failures.
